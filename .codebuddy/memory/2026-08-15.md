## 答疑：zero 模块计数语义与 uint32_t 溢出
- 用户困惑点 1：s_zero_count 是"次数"不是"时间"，只在中断通过去抖后 +1；间隔 10ms 两次触发后 count=2（首次 0→1，第二次 1→2，10ms ≥ 5ms 不会被去抖吞掉）。时间信息应看 Zero_GetHalfPeriod/FullPeriod/LastTick/Systick_GetTickMs，count 只用于统计次数。
- 用户困惑点 2：运行 100 天是否超时。uint32_t 毫秒计数约 49.7 天回绕，100 天必溢出；但差值运算（interval、主循环超时判断）用无符号减法，取样跨度 <49.7 天即结果正确，不受影响。唯一边界瑕疵：s_zero_last_tick 回绕到 0 瞬间误判"首次触发"，跳过一次半周期测量，无累积误差。绝对时间用途（显示运行时长/日志时间戳）需改 uint64_t 毫秒计数；s_zero_count 每秒约 100 次，约 497 天才溢出。
- 用户对 zero 模块的实时性/健壮性关注点：信号丢失时中断不触发，间隔检测与计数全部失效（纯事件驱动被动系统），建议主循环用 Systick_GetTickMs() - Zero_GetLastTick() 做超时检测（如 >100ms 判市电异常）。

## 新增串口模块 uart（与显示板通信，V1.0.0）
- 新建 `MOVA/User/uart.h` + `uart.c`：USART1 @ PA2(TX)/PA3(RX)，GPIO_AF_1，115200-8-N-1，中断优先级 2U（SysTick=0、EXTI0_1=1、USART1=2）。
- 选型原因：GD32E23x 的 USART0 默认在 PA9/PA10（AF1，官方例程 GD32E230C_EVAL 04_USART_Printf 确认），但 PA9 已被风扇占用；PA2/PA3 为 USART1 复用引脚（AF1），空闲，故用 USART1。
- 功能：Uart_Init / Uart_SendByte / Uart_SendData / Uart_SendString（轮询 TBE+TC 阻塞发送）/ Uart_RxAvailable / Uart_RxRead（中断 RBNE + 环形缓冲 64B，满则丢新数据）/ Uart_IrqHandler。
- 集成：gd32e23x_it.h/.c 新增 USART1_IRQHandler → Uart_IrqHandler；main.c 增加 Uart_Init() 调用，主循环加"收到即回发"回显示例（后续替换为显示板协议）；MOVA.uvprojx 的 User 组已加入 uart.c。
- 注意：uart.c 需在 Keil 重新编译验证；引脚/波特率集中在 uart.c/h 宏，换引脚只改 uart.c 顶部 4 个宏 + uart.h 的 UART_BAUDRATE。

- main.c 主循环改为"回显+日志"演示：收到数据 → Uart_SendData 原样回发 → printf("[RX %uB] ") + 内容 + \r\n。后续替换为显示板协议解析。
