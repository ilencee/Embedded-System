# 2026-08-17

## 修复 12VON 电源控制模块（12VON.c / 12VON.h）

- 原始代码致命问题：所有标识符以数字 `12` 开头（`12VON_PIN`、`12VON_Init` 等），C 语言标识符不能以数字开头 → 整个文件无法编译；include guard `__12VON_H__` 同样非法。
- 修复：统一改名 `12VON_*` → `V12ON_*`（合法标识符），补齐文件头注释与 extern "C"。
- 原 `12VON.c` 用的 `RCU_EnableClock()` API 在 GD32E23x 库不存在（正确为小写 `rcu_periph_clock_enable()`），且宏名不匹配；已改用 `rcu_periph_clock_enable(V12ON_GPIO_CLK)`，并补齐 GPIO 推挽输出配置 + 默认关 + `V12ON_Set/Reset/Toggle` 实现。
- 过程中用户手动插入过一行 `RCU_PeriphClock_Enable(V12ON_GPIO_CLK);`（大写 API 同样不存在，且与正确调用重复），已删除。
- 用 MinGW gcc + 临时 stub 头文件做了 `-fsyntax-only` 验证，通过。
- **⚠️ 引脚冲突提醒：12VON 使用 PA5，而昨天新增的 DS1302(1302.c) 默认 SCLK=PA5 —— 两者同时启用会冲突，需用户确认硬件实际接线后调整其中一个的引脚宏。**
- 注意：12VON.c/h 均未加入 Keil 工程（uvprojx 无引用），需手动添加后才参与编译。
- 遗留：验证用的临时目录 `MOVA/.tmp_verify/`（含 stub 头文件）仍在磁盘上，用户拒绝了删除命令，待用户自行清理。
- **2026-08-17 补充：用户确认 12VON 实际引脚为 PB8**（`GPIO_PIN_8` / `GPIOB` / `RCU_GPIOB`），已更新 `12VON.h` 宏 `V12ON_PIN/V12ON_GPIO/V12ON_GPIO_CLK` 及 `12VON.c` 注释；与 DS1302 的 PA5 冲突问题随之解除（PB8 不与任何现有外设冲突）。
